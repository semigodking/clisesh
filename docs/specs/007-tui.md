# Spec 007 — TUI

Status: Implemented (Tasks 8 & 9)

## Purpose

A Bubble Tea full-screen picker that lists sessions with themed styling,
supports navigation and multi-select, filtering, manual description editing, an info popup,
an error inspection modal, deletion (with cascade where supported), re-summarization, and resume — all gated by the
active provider's capabilities.

## Background startup summarization

To provide instant startup without blocking the user interface:

1. `classifyDescriptions` resolves descriptions that need no LLM (trusted cache
   hits and empty sessions) and collects the rest into a `missing` set.
2. The full-screen interactive TUI opens **immediately** with zero delay.
   Sessions pending summarization initially display `Summarizing…` (or `Queued for summary…`).
3. `Model.Init()` automatically schedules background worker pool summarization for any
   pending sessions off the UI thread via `context.WithCancel`.
4. While summarization is in flight, the user can freely navigate, filter,
   inspect, delete, edit descriptions, or resume sessions.
5. When individual sessions complete:
   - Results are delivered via a message into `Update`.
   - Descriptions update reactively 1-by-1 in the list and disk cache.
   - The status line reports `summarized N session(s)` once all tasks finish.
6. If the user chooses to resume a session (presses `Enter`) or quits (`q`),
   `cancel()` is invoked immediately, aborting in-flight tasks cleanly.

## Model

```go
type Model struct {
    provider   domain.SessionProvider
    summarizer summarize.Summarizer
    cache      *cache.Cache
    theme      theme.Theme
    caps       domain.Capabilities

    sessions []domain.Session   // full set (newest first)
    cursor   int                // index into filtered view
    offset   int                // scroll offset
    marked   map[string]bool    // selected ids
    mode     mode               // normal | filter | confirmDelete | info | error | editDesc
    filter   string             // current filter text
    width, height int
    status   string             // transient status message
    resumeID string             // set when the user chose to resume

    editInput     textinput.Model // textinput for manual editing
    editSessionID string
}
```

`mode` is one of `modeNormal`, `modeFilter`, `modeConfirmDelete`, `modeInfo`, `modeError`, `modeEditDesc`.

## Layout (top to bottom)

1. **Header** (theme `Header`, full width): app title + provider name.
2. **List** (remaining height): one row per visible session.
3. **Status row** (theme `Status`, full width): filter prompt + input text (`Filter: <query>▌` in filter mode, with top priority over background status), transient status, mark count, or the cursor session's id + cwd; right-aligned `pos/total`.
4. **Footer** (theme `Footer`, full width): capability-gated key hints with styled key badges.

### Row columns (fixed, uniform for all row states)

`" M L BBB  AGE  [SHORTID]  DESCRIPTION"` where:
- `M` mark indicator (1 col) + space
- `L` lock indicator (1 col) + space
- `BBB` provider badge (3 cols) + two spaces — a standardized 3-character uppercase badge identifying the CLI provider (`AGY`, `KIR`, `CLD`, `CDX`, `OPC`), rendered in each tool's brand color
- `AGE` right-justified to 9 cols + two spaces
- `[SHORTID]` 10 cols (`[`+8+`]`) + two spaces
- `DESCRIPTION` truncated to remaining width

## Actions (capability-gated)

| Key      | Action                                        | Gate                |
|----------|-----------------------------------------------|---------------------|
| `enter`  | resume cursor session (normal mode)           | `CanResume`         |
| `space`  | toggle mark on cursor, advance                | always              |
| `/`      | enter filter mode                             | always              |
| `m`      | manually edit description in modal            | always              |
| `i`      | show info popup for cursor session (scrollable)| always              |
| `e`      | open scrollable error details modal           | when error active   |
| `r`      | re-summarize marked (or cursor) sessions      | `ProvidesPrompts`   |
| `d`      | begin delete confirmation                     | `CanDelete`         |
| `y`      | confirm delete (in confirmDelete mode)        | `CanDelete`         |
| `q`/`ctrl+c` | quit application                          | always              |
| `esc`    | leave filter, edit, error, or dialog mode     | modal modes only    |

*Note: In normal mode, pressing `Esc` is intentionally a no-op to prevent accidental exit.*

### Resume Validation (`ValidateResume`)
When the user presses `Enter` on a session:
- `m.provider.ValidateResume(ctx, sessionID)` is called prior to tearing down the TUI.
- If the target CLI binary is missing on PATH (or validation fails), clisesh remains open, transitions to `modeError`, and opens the error modal detailing the missing executable and installation instructions.

### Manual Description Editing (`m`)
- Pressing `m` opens an inline textinput dialog pre-filled with the current description (or session title fallback).
- Pressing `Enter` saves the edited description immediately to the session row and disk cache.
- Pressing `Esc` cancels editing without saving.

### Filter Mode (`/`)
- Typing alphanumeric runes dynamically filters the session list and updates the status row (`Filter: <query>▌`).
- `↑` / `↓` (and `PgUp` / `PgDn`) navigate the highlighted session directly within the filtered list.
- `Tab` / `Ctrl+I` / `Alt+I` opens the session info modal for the highlighted session; closing it returns seamlessly to filter mode with the active query preserved.
- `Enter` applies the filter and returns to normal mode.
- `Esc` clears the filter query and returns to normal mode.
- `Ctrl+C` quits the application.

## Testability

`Model.Update(msg)` is pure and testable without a TTY. Tests cover cursor
movement bounds, mark toggling, filter matching, capability gating, manual description editing,
worker pool progressive refill, and failure restoration.
